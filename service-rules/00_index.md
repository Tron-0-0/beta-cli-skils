# Правила разработки: Java / Spring Boot сервис

Универсальный style-guide для микросервисов на **Java / Spring Boot** (REST + JPA, опционально Kafka). Не привязан к конкретному репозиторию — переиспользуется как стартовый набор соглашений для любого сервиса на этом стеке и дорабатывается под специфику проекта по мере необходимости.

## Приоритет

1. **Корпоративный регламент** (если в организации есть единый стандарт разработки/архитектуры) — обязателен, эти правила его не отменяют.
2. **Правила этого набора** — конкретизируют общепринятые практики Java/Spring, где регламент их не покрывает.
3. **Локальные соглашения конкретного репозитория** — если фактический код проекта расходится с этими правилами осознанно (например, из-за унаследованной архитектуры), локальное решение фиксируется отдельно и имеет приоритет только в рамках этого репозитория.

## Как применять к конкретному репозиторию

Эти правила — стартовый набор, а не готовый отчёт по вашему коду. При подключении к реальному проекту:

1. Сверь фактические пакеты/модули/стек с `00_project_creation.md` и адаптируй примеры под реальные имена классов.
2. Если код репозитория осознанно отклоняется от правила (например, другой паттерн API-контракта) — зафиксируй это как локальное дополнение поверх соответствующего файла, а не переписывай общее правило.
3. При появлении в проекте новых тем (Kafka, специфичный protocol, специфичная БД) — расширяй набор новым файлом по той же структуре.

## Как обновлять

Пересматривай файлы при смене мажорной версии Spring Boot/Java, появлении новых общепринятых практик в экосистеме или после существенного архитектурного решения, которое должно стать соглашением команды.
