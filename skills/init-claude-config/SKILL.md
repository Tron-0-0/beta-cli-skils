# init-claude-config

Заводит `.claude/` в целевом проекте по образцу репозитория-шаблона
[Tron-0-0/beta-cli-skils](https://github.com/Tron-0-0/beta-cli-skils) — источника
базовых правил (`rules/`), скиллов (`skills/`) и хуков (`hooks/`), которые
считаются отправной точкой, а дальше дорабатываются уже в контексте
конкретного проекта.

## Зачем так, а не просто git clone поверх

Целевой проект может уже иметь собственный `.claude/`, частично
кастомизированный под себя (свои правила, свои версии скиллов). Слепой
`git clone`/перезапись стёрла бы эту доработку. Поэтому синхронизация — это
"долив недостающего": каждый файл из шаблона копируется в проект, только если
там ещё нет файла с таким же путём. Если файл уже существует — он не
трогается, даже если содержимое в шаблоне с тех пор изменилось. Это и делает
скилл безопасным для повторного запуска (например, когда в beta-cli-skils
появился новый скилл, а остальное в проекте трогать не нужно).

## Шаги

1. Определить целевой каталог проекта. Если пользователь явно не указал путь,
   это текущий рабочий каталог.
2. Запустить скрипт синхронизации:
   ```bash
   scripts/sync_claude_dir.sh <target_project_dir>
   ```
   Каталог можно не указывать, если это текущая директория. Если пользователь
   называет свой репозиторий-шаблон вместо `beta-cli-skils` — передать его через
   `--repo <git-url>`.
3. Скрипт сам:
   - клонирует репозиторий во временный каталог (`--depth 1`, без мусора в
     истории);
   - берёт с его верхнего уровня все каталоги, кроме скрытых (сейчас это
     `rules/`, `skills/`, `hooks/` — но скрипт не хардкодит эти имена, так что
     если в шаблоне позже появится ещё один каталог верхнего уровня, он
     подхватится автоматически);
   - для каждого файла: копирует в `.claude/<каталог>/...`, только если такого
     файла там ещё нет;
   - выводит списком, что добавлено и что пропущено (уже было).
4. Пересказать пользователю итог своими словами: сколько файлов добавлено (с
   перечислением), сколько пропущено как уже существующих. Не нужно дублировать
   сырой вывод скрипта построчно, если список длинный — достаточно сводки плюс
   пары примеров.
5. Если среди добавленного есть файлы из `hooks/` — обязательно предупредить
   отдельно: сами по себе `.sh` скрипты не подключены ни к одному событию, это
   не делает их рабочими хуками. Чтобы Claude Code их реально вызывал, нужно
   прописать привязку (событие → команда) в `.claude/settings.json` — это вне
   ответственности этого скилла; для этого шага предложить скилл `update-config`
   или сослаться на документацию хуков.

## Что не входит в задачу этого скилла

- Не создаёт и не трогает `CLAUDE.md`, `.claude/settings.json`,
  `.claude/agents/` — шаблон описывает только `rules/skills/hooks`, остальное
  специфично для проекта и должно настраиваться отдельно.
- Не мёрджит содержимое файлов и не показывает diff для существующих файлов —
  правило простое: файл есть → не трогаем, файла нет → копируем целиком.
- Не пушит ничего обратно в репозиторий-шаблон — синхронизация всегда
  однонаправленная, из шаблона в проект.
