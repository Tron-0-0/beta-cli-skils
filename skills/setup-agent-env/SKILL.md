# Окружение агента: развёртывание и проверка

Скилл воспроизводит на этом компьютере проверенное окружение агента: MCP-серверы
уровня пользователя, языковые серверы для agent-lsp, хуки, которые заставляют
проверять правленые файлы, и профили БД. Всё делает идемпотентный скрипт — его можно
запускать сколько угодно раз, он трогает только то, чего не хватает.

Состав, версии, причины решений и известные проблемы — в
[references/components.md](references/components.md). Загляни туда, если скрипт
сообщил о проблеме, которую не исправляет сам, или если нужно обновить версию.

## 1. Проверка

```bash
<папка скилла>/scripts/setup.sh check
```

Скрипт ничего не меняет и печатает по шагам, что на месте (✓), чего нет (✗) и что
стоит знать (!). Покажи пользователю итог кратко: что уже настроено и что будет
сделано. Если всё зелёное — переходи сразу к шагу 4.

Скрипт не ставит Homebrew и Claude Code CLI (без них останавливается) и не ставит
Docker (только предупреждает) — подскажи пользователю установить их вручную.

## 2. Установка

Получи согласие пользователя — `apply` ставит пакеты глобально (Homebrew, npm),
скачивает jar из Maven Central и repo.eclipse.org (со сверкой SHA-1), регистрирует
MCP-серверы и дополняет `~/.claude/settings.json` (с копией `settings.json.bak`;
существующие ключи не перезаписываются). Затем:

```bash
<папка скилла>/scripts/setup.sh apply
<папка скилла>/scripts/setup.sh check   # должно быть «Окружение настроено полностью»
```

Если какой-то шаг не прошёл (сеть, права, нет формулы) — разберись по выводу,
исправь причину и повтори `apply`: уже сделанное он пропустит.

## 3. Профили БД

У postgres MCP один сервер на все проекты, а подключение к каждой БД — отдельный
профиль только на чтение. Спроси пользователя, для каких проектов нужны профили, и
где лежат их env-файлы с параметрами подключения (обычно `~/.config/<проект>/<проект>.env`
с переменными `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`). Секреты
в репозиторий не попадают — на новом компьютере эти файлы пользователь переносит сам;
если файла нет, профиль не создавай, а скажи, чего не хватает.

```bash
<папка скилла>/scripts/pg-profile.sh <имя-профиля> <env-файл> [префикс-переменных]
```

Пароль уходит в Связку ключей macOS и не печатается. Повторный запуск обновляет
профиль — так же действуй, если пароль БД сменился. Сам агент профили создавать и
удалять не может: эти инструменты запрещены в `settings.json` намеренно, чтобы нельзя
было обойти режим только чтения.

## 4. Проверка серверов

Новые MCP-серверы подхватываются только после `/mcp` (переподключение) или
перезапуска Claude Code — попроси пользователя сделать это, потом проверь работу
вживую. Файлы для проверки клади во временную папку **внутри текущего проекта**
(agent-lsp отвергает пути вне рабочей папки), в конце удали её.

1. Для каждого типа создай файл с намеренной ошибкой и вызови
   `mcp__agent-lsp__get_diagnostics` с `file_path`:
   - `.java` без `;` → `Syntax error, insert ";"` (вне classpath — только синтаксис);
   - `.yaml` с `a: [1` → `Flow sequence ... must end with a ]`;
   - `.json` с `{"a": 1,, }` → `Property expected`;
   - `.py` с `x: int = "s"` → `reportAssignmentType`;
   - `.xml` с `<a></b>` → `ETagRequired`;
   - `.sql` с `SELEC 1;` → `Invalid statement: syntax error`.

   Ответ «No diagnostics received» — сервер ещё не успел, повтори вызов.
2. Исправь один файл через Edit и сразу проверь снова — ошибка должна исчезнуть
   (проверяет хук `close_document`; без него JSON-сервер ответит устаревшим состоянием).
3. Если в проекте есть Java-код — `mcp__agent-lsp__blast_radius` по любому классу с
   Lombok: должны найтись вызывающие, без ложных ошибок Lombok.
4. jarpeek: `mcp__jarpeek__find_class` по классу из зависимости проекта (например,
   `org.springframework.boot.SpringApplication`).
5. postgres (если есть профиль и БД запущена): `postgres_mcp_list_connection_profiles`,
   `postgres_mcp_connect` с id профиля, `postgres_mcp_query` с `SELECT 1`. Убедись, что
   запись недоступна: вызов `postgres_mcp_modify` должен быть отклонён.

По ходу хуки будут напоминать проверить созданные файлы и не дадут завершить работу,
пока проверка не сделана, — это и есть проверка самих хуков.

## Итог для пользователя

Коротко: что было и что сделано, результат `check`, какие профили БД созданы, итоги
проверки серверов (по каждому — работает или нет) и что осталось сделать вручную
(Docker, перенос env-файлов, `/mcp`).
