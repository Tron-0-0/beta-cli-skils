# Соглашение: Файлы в `specification/`

**Когда читать:** перед созданием, переносом или удалением любого `.md` файла или папки в `specification/`.

**Что описывает:** теги во frontmatter и файлы `index.md`, через которые устроена навигация по спецификации.

---

## 1. Правило

- Каждый `.md` файл в `specification/` начинается с frontmatter с тегом своего раздела. Тег выбирается по папке, в которой лежит файл:

  | Папка | Тег |
  |---|---|
  | `increment/` (всё внутри: `index.md`, `done.md`, артефакты задач) | `increment` |
  | `absolut/` | `specification` |
  | `roadmap/`, а также `ideas.md` | `tasks` |
  | любая другая папка (`libraries/`, `align-with-rules-reports/` и новые) | `specification` |

  Корневой `specification/index.md` охватывает все разделы, поэтому тега у него нет.
- В каждой папке `specification/` лежит `index.md`. Новая папка создаётся сразу вместе со своим `index.md`.
- Каждый файл и каждая подпапка упомянуты в `index.md` своей папки ссылкой с описанием в одну строку: файл — `[`имя.md`](имя.md)`, подпапка — `[`имя/`](имя/index.md)`.
- Новый файл добавляется в `index.md` в том же коммите, в котором появляется сам. Удалённый или перенесённый файл убирается из индекса в том же коммите.
- Строка в `index.md` дописывается к уже существующим строкам и не перезаписывает их.

Формат frontmatter:

```markdown
---
tags:
  - increment
---

# Заголовок
```

## 2. Проверка

`.claude/scripts/check-spec-index.sh` проверяет все три требования и печатает нарушения построчно. Код выхода `1` означает, что нарушения есть. Скрипт запускают `update-spec` перед коммитом и `pipeline-status` при показе прогресса.

## 3. Обоснование

Спецификацию удобно открывать как хранилище Obsidian: теги позволяют отфильтровать разделы (описание проекта, инкременты, задачи), а `index.md` даёт навигацию по папке без поиска по файлам. Индекс, в котором нет части файлов, хуже его отсутствия: читатель считает его полным.

## 4. Чек-лист самопроверки

- [ ] У нового файла есть frontmatter с тегом из таблицы.
- [ ] Новый файл упомянут в `index.md` своей папки.
- [ ] У новой папки есть `index.md`, и она упомянута в `index.md` родительской папки.
- [ ] `.claude/scripts/check-spec-index.sh` завершается без нарушений.

## 5. Примеры

Правильно — `specification/increment/r<версия>/<ветка>/index.md` после шага `form-plan`:

```markdown
## Файлы

- [`intent.md`](intent.md) — намерение: цель, скоуп, критерии готовности (`form-intent`).
- [`system-intent.md`](system-intent.md) — системный анализ: процесс, поток данных, связь с архитектурой (`form-system-intent`).
- [`plan.md`](plan.md) — план реализации на уровне кода (`form-plan`).
- [`pipeline-state.md`](pipeline-state.md) — состояние пайплайна задачи по шагам.
```

Неправильно:

```markdown
# План реализации: <короткое имя задачи>     # нет frontmatter с тегом increment
```
